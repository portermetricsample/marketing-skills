# Design — principles for your dashboards

When the output is a dashboard or a written report, apply these five principles so your
insights and recommendations are clear and easy to grasp. (From the SUMAS dashboard-design
guide; deeper component rules live in [`../porter-reporting/`](../../reporting/porter-reporting/).)

| Principle | What it means | In practice |
|---|---|---|
| **Hierarchy** | Size and position reflect priority | Put the metric that matters most (e.g. ROAS, spend) biggest and top-left; supporting metrics smaller. |
| **Contrast** | Highlight the priority metric with color and size | Give the one number the reader came for visual weight; mute the rest. |
| **Consistency** | Same colors, formats, layouts and shapes across the report | A channel keeps the same color everywhere; every card uses the same number format — it makes the report feel "familiar". |
| **Redundancy** | Make the insight obvious | Don't make the reader hunt. Call it out with color, a text note, or an annotation ("↓ CPA up 32% — TikTok"). |
| **Reduce cognitive load** | Say explicitly whether a metric is good or bad | Use conditional formatting (green = good, red = bad) so direction reads at a glance, not by mental math. |

**Rule of thumb:** a good ads dashboard can be read in 10 seconds — the reader should see
*where the money goes*, *what it's buying*, and *what's off* without studying it.
