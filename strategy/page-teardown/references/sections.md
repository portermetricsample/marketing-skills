# Page components (sections)

The jobs a page has to do. Each one can **be** a section, **share** one, or **run through** all of them. In a teardown, tag every section on the page with one of these, in order — that ordered list is the **outline**.

| Component | What it does |
|---|---|
| **Hero** | States what this is and who it's for |
| **Audience** | Names the reader (sometimes segmented into tabs/blocks) |
| **Problem** | Shows the current state and its cost |
| **Solution** | The outcome, and how it's reached |
| **Benefits** | What the reader gains |
| **Features** | What makes the outcome possible |
| **Reference** | The complete list someone scans for one item (integrations, supported tools) — answers the **Fit** objection |
| **Use cases** | The abstract made concrete |
| **Community** | The ecosystem around the product — tutorials, templates, support (answers Effort / Risk: you won't be left alone) |
| **Transformation** | The reader's situation before and after |
| **Comparison** | Contrasts the current way of working with the new one |
| **Differentiation** | Why this one and not the alternatives |
| **Social proof** | That others already did this |
| **Pricing** | What it costs, and on what basis |
| **FAQs** | The questions left over |
| **Close** | The final call to act — restates the outcome, repeats the CTA |

**Selection & order aren't free choice** — they're driven by the **sequence × awareness level** ([`sequences.md`](sequences.md), [`awareness.md`](awareness.md)). Each section is a *container* that presents substance — a "Problem section" is the pain, dressed as a section.

> **Reference vs Features — same source, opposite job.** Features *argues* (length is a cost — pick the few that matter); Reference *gets scanned* (completeness is the value — an integrations list). A Reference section answers **Fit** at the finest grain a reader can ask it — *"is my tool covered?"* — so an incomplete list is worse than a short one.

**Sections omitted are a finding.** Note which jobs the page *doesn't* do. A page with no Problem, no Pricing, no Comparison and no FAQ is telling you what it's betting on (and what it's ducking).
