# Angles

How a page (or a section) tells its argument. In a teardown, name the **dominant** angle and any secondary ones — a page often runs a before/after spine over a listicle of capabilities. Angles combine; one usually leads.

| Angle | What it does |
|---|---|
| **Before/after** | The transformation — where you are now vs where you'll be |
| **Listicle** | N elements — features, use cases, benefits, steps |
| **Comparison** | A vs B — this way of working vs the old one |
| **Difference** | Two things people confuse, and where the line is |
| **Decode** | Explain how something works, or how a company does its thing |
| **Framework / method** | The named system for doing X — the parts and how they connect |
| **Product launch** | Announce something new — "X now does Y" |
| **Archetypes** | Contrast types of reader ("whoever you are: creators / SMBs / agencies") and speak to each |
| **Contrarian** | Everyone says A; the truth is B |
| **Hack / shortcut** | A quick, maybe unknown way to get the outcome |
| **Day in the life** | A real workflow, tool by tool, task by task |
| **Maturity levels** | The same practice shown at ascending stages |
| **Story** | A narrative — founder, customer, or category journey |

**Reading it:** the angle shapes the *body* of the argument, where the sequence shapes the *whole* page. A page can run a promise-first sequence and tell it through a before/after angle — name both.
