# Copy-component structure — the skim test

A well-built section is written as a **descent**: each rung earns the read of the next, and the type steps down in weight as it goes. A reader can **stop at any rung** and still have the point.

| Rung | Its job |
|---|---|
| **Headline** | the promise |
| **Subheadline** | describes the headline |
| **Bold keyword label** | the item's main idea (inline bold, body size) |
| **Body** | the elaboration (feature → benefit) |

Two things fall out of this, and both are teardown checks:

- **The cascade must survive a skim.** A reader who reads *only* the headlines and the bold labels should still get the whole story, in order. If the bold path alone doesn't make sense — or there's no bold path at all — the copy is leaning on the visuals to carry meaning.
- **Consistent block shapes read as a system.** Recurring sections (feature blocks, use-case blocks) should follow the same shape every time. High consistency reads as considered; a different shape each time reads as improvised.

## The use-case / feature block

The common shape for a product or use-case section:

```
HEADLINE     the promise, benefit-framed
SUBHEAD      one line describing the headline
ITEMS ×3–5   each one line:
   **Keyword label:** feature, translated into the benefit
```

**Generic example:**

> **One dashboard for every channel.**
> See paid, organic, and email side by side, updated daily, without a spreadsheet.
>
> - **Live connectors:** pull each platform automatically, so numbers are never stale
> - **Blended view:** compare channels on the same metric to find where budget works hardest
> - **Scheduled exports:** send the report on a cadence, so nobody has to remember

**In a teardown**, record: does each section descend the ladder? Is there a bold path, and does it survive a skim on its own? How consistent are the recurring blocks? A page that carries its story only in headlines + product screenshots (no bold path) is a common, legitimate — but flaggable — pattern.
